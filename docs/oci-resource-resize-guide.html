관찰한 증상에 맞는 자원만 조정하세요.

디스크 사용률이 높다 → 부트 볼륨

df -h /의 여유 공간이 부족할 때. 현재 100GB로 늘렸고, 서버에서 약 66GB 여유를 확인했습니다.

메모리 부족·스왑 입출력 → RAM

free -h의 available이 지속적으로 낮고 스왑 입출력이 반복될 때. 예: 4GB에서 8GB.

CPU가 지속적으로 포화 → OCPU

트래픽 처리 중 CPU 사용률이 오래 높을 때. 디스크 부족만으로 OCPU를 늘릴 필요는 없습니다.

콘솔 시작점OCI 오사카 인스턴스 목록에서 mock_kabu를 선택합니다. 아래 경로는 OCI 화면 언어가 한국어일 때의 표시를 기준으로 합니다.
1

RAM 또는 OCPU 바꾸기

두 값은 인스턴스의 셰이프 설정에서 함께 편집합니다.

서비스 중단이 생깁니다실행 중인 인스턴스의 셰이프를 저장하면 OCI가 재부팅합니다. 거래 서비스라면 점검 시간을 정하고 백업 상태를 확인한 뒤, 가능하면 OS를 정상 종료한 상태에서 변경하세요.

  1. 현재 값과 목표를 정하기

    현재는 2 OCPU · RAM 4GB입니다. 메모리만 필요하면 예를 들어 2 OCPU · RAM 8GB로 설정합니다. CPU까지 필요한 경우에만 OCPU를 늘립니다. 선택 가능한 조합과 비용은 콘솔에 표시된 값을 확인하세요. 점검 시간이 시작되면 서버의 작업을 마친 뒤 SSH에서 sudo shutdown -h now로 정상 종료하고 OCI 상태가 중지됨인지 확인하는 방법이 안전합니다.

  2. 인스턴스 편집 열기

    OCI에서 mock_kabu 인스턴스를 연 뒤 다음 경로로 이동합니다.

    작업 → 추가 작업/편집 → 셰이프 요약 → 셰이프 편집

    콘솔 버전에 따라 ‘추가 작업 → 편집’ 또는 ‘작업 → 추가 작업 → 편집’으로 보일 수 있습니다.

  3. 셰이프와 수치 저장하기

    기존 VM.Standard.E3.Flex를 유지한 상태에서 OCPU 개수와 메모리(GB)를 입력하고 변경사항 저장을 누릅니다. 실행 중이라면 재부팅 확인 창이 나옵니다. 중지 상태에서 변경했다면 저장 후 인스턴스를 시작합니다.

  4. 부팅 후 확인하기

    SSH로 다시 접속한 다음 아래 명령으로 새 RAM·CPU 수와 컨테이너 상태를 확인합니다. x86 E3에서 2 OCPU는 보통 게스트 OS에 4개의 논리 CPU로 보입니다.

    free -h
nproc
docker ps

참고: Oracle 공식 셰이프 변경 절차. 이미지 호환성·서비스 한도에 따라 일부 셰이프나 값은 선택할 수 없습니다.

2

부트 볼륨 늘리기

OCI 크기 변경 → Ubuntu 장치 재검색 → 파티션 확장 → ext4 확장 순서입니다.

이 서버는 47GB → 100GB 증설 완료현재 콘솔은 100GB, 서버의 df -h /는 약 96GB 전체·66GB 여유를 표시합니다. 아래 절차는 다음에 다시 증설할 때 적용합니다.

  1. 복구용 백업 만들기

    mock_kabu 인스턴스의 스토리지 탭에서 mock_kabu (Boot Volume)을 엽니다. 백업 → 부트 볼륨 백업 생성 → 전체 백업을 선택하고 상태가 사용 가능이 될 때까지 기다립니다. 2026-09-23 증설 전 백업 이름은 mock-kabu-pre-resize-2026-09-23입니다.

  2. OCI에서 기존 부트 볼륨 편집

    부트 볼륨 상세 화면의 편집 → 볼륨 크기(GB)에 더 큰 값을 입력하고 업데이트를 누릅니다. 새 블록 볼륨을 생성하는 방식은 현재 루트 디스크 /를 늘리지 않습니다. 기존 균형 조정 성능(VPU/GB: 10)은 별도 성능 문제가 없다면 그대로 둡니다.

    OCI는 볼륨 크기를 줄일 수 없습니다. 저장 전 목표값과 비용·무료 할당량을 확인하세요.

  3. 서버 장치와 파일시스템 종류 확인

    OCI 화면에서 새 크기와 사용 가능 상태를 확인한 후 SSH로 접속합니다. 이 서버의 루트는 /dev/sda1의 ext4이며, 다른 서버에서는 장치명이 다를 수 있습니다.

    findmnt -n -o SOURCE,FSTYPE /
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT

  4. 새 디스크 크기 인식시키기

    lsblk에서 sda가 아직 이전 크기라면 재검색합니다. OCI 완료 안내 창의 명령이 다르면 해당 장치 경로를 우선 확인하세요.

    sudo dd iflag=direct if=/dev/sda of=/dev/null count=1
echo 1 | sudo tee /sys/class/block/sda/device/rescan
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT

  5. 파티션과 ext4 확장

    sda가 새 크기이고 sda1만 이전 크기일 때 실행합니다. findmnt 결과가 이 서버의 /dev/sda1 ext4와 다르면 여기서 멈추고 해당 파일시스템에 맞는 절차를 확인하세요.

    sudo growpart /dev/sda 1
sudo resize2fs /dev/sda1
df -h /

참고: 변경 전 백업·축소 불가, 온라인 부트 볼륨 증설, Linux 장치 재검색, Oracle의 growpart/resize2fs 예시.

변경 후 확인

콘솔 값과 서버에서 실제 사용할 수 있는 값이 모두 맞아야 완료입니다.

free -h
nproc
df -h /
docker ps

디스크 증설 전후 실제 확인값: 45G / 30G 사용 / 15G 여유 → 96G / 30G 사용 / 66G 여유. 거래 컨테이너는 확장 후에도 실행 중이었습니다.

막힐 때 확인

반복 실행 전에 어느 단계가 끝났는지 확인하세요.

증상확인할 부분
OCI는 새 크기, lsblk의 디스크는 이전 크기볼륨 상태가 사용 가능한지 기다린 뒤 장치를 재검색합니다.
디스크는 새 크기, df -h /는 이전 크기growpart와 resize2fs가 끝났는지 확인합니다.
RAM/OCPU 변경 후 SSH 접속이 끊김셰이프 변경에는 재부팅이 따릅니다. OCI의 인스턴스 상태가 실행 중인지 확인합니다.

무료 체험과 과금

자원 화면의 무료 표시와 컴퓨트 셰이프의 무료 여부를 각각 확인하세요.

2026-09-23 현재 이 부트 볼륨은 OCI 콘솔에 상시 무료로 표시됩니다. 계정은 무료 체험 중이지만 VM.Standard.E3.Flex는 Oracle의 상시 무료 컴퓨트 셰이프 목록에 포함되지 않습니다. 체험 종료 후에도 같은 셰이프를 계속 운영하려면 계정 상태와 요금을 확인해야 합니다.

비용은 리전, 실제 사용 시간, 무료 할당량, 볼륨 성능 설정에 따라 달라집니다. 변경 전 콘솔 예상 요금과 Oracle 가격표, 상시 무료 대상을 확인하세요.
