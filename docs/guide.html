mock kabu 2 · 로컬 모의 거래소

주문부터 정산까지,
전 구간이 내 노트북 안에서.

지정가·시장가 주문을 인메모리 오더북이 가격–시간 우선으로 매칭하고, 봇 10개와 가상 뉴스가 호가창을 계속 움직입니다. PostgreSQL과 Redis만 Docker로 띄우면 나머지는 전부 로컬 프로세스입니다.

웹

API
http://localhost:4100 NestJS · REST + WebSocket
필요한 것
Node.js 22+ · pnpm · Docker Desktop

최초 1회

설치부터 첫 주문까지

아래 다섯 단계는 처음 한 번만 필요합니다. 두 번째부터는 두 줄이면 됩니다.

  1. 의존성 설치

    pnpm install

  2. 환경변수 파일 생성

    기본값 그대로 써도 됩니다.

    cp .env.example .env
cp packages/db/.env.example packages/db/.env

  3. 인프라 기동

    PostgreSQL 16 + Redis 7 컨테이너가 올라옵니다.

    pnpm infra:up

  4. 마이그레이션 + 시드

    종목 7개와 봇 계정 10개가 만들어집니다. 이 단계만 최초 1회입니다.

    pnpm db:migrate
pnpm db:seed

  5. 전체 기동

    api · settlement · matching-engine · bots · web이 한 번에 뜹니다.

    pnpm dev

    localhost:3100 접속 → 회원가입(가상 현금 1,000만원 지급) → 종목 선택 → 매수·매도.

두 번째 실행부터

DB 데이터는 Docker 볼륨에 남으므로 마이그레이션·시드는 다시 하지 않습니다.

pnpm infra:up
pnpm dev

Docker

켜는 명령 하나, 끄는 명령 하나.

Compose 프로젝트 이름이 mock-kabu2로 고정되어 있어, 같은 머신의 다른 프로젝트 컨테이너와 섞이지 않습니다.

시작

pnpm infra:up
# = docker compose --project-name mock-kabu2 up -d

postgres · redis 두 컨테이너가 백그라운드로 뜨고, healthcheck가 통과하면 준비 완료입니다.

종료

# 1) 앱 종료: pnpm dev 터미널에서 Ctrl+C
pnpm infra:stop
# = docker compose --project-name mock-kabu2 stop

컨테이너만 멈추고 데이터는 그대로 남습니다. WSL 메모리까지 반환하려면 wsl --shutdown.

상태 확인

docker compose --project-name mock-kabu2 ps
docker compose --project-name mock-kabu2 logs -f postgres

데이터 보존

Docker를 꺼도 거래 데이터는 남습니다.

계좌·주문·체결·원장·캔들은 전부 named volume에 저장됩니다. 컨테이너를 지워도 볼륨은 따로 살아 있어서, 다시 올리면 껐던 시점 그대로 이어집니다. 초기화되는 경우는 볼륨을 명시적으로 지울 때뿐입니다.

명령컨테이너데이터다시 켤 때
pnpm infra:stop 정지 유지 pnpm infra:up만
pnpm infra:down 삭제 유지 pnpm infra:up만
PC 재부팅 · Docker 재시작 정지 유지 pnpm infra:up만
down -v 삭제 전부 삭제 migrate + seed부터 다시
pnpm db:seed 영향 없음 시드 데이터 덮어씀 —

데이터가 실제로 사는 곳

mock-kabu2-pgdata → /var/lib/postgresql/data

mock-kabu2-redisdata → /data (appendonly)

이름이 고정된 볼륨이라 컨테이너를 몇 번 지웠다 만들어도 같은 볼륨에 다시 연결됩니다.

포트

PostgreSQL · localhost:55432 → 5432

Redis · localhost:56379 → 6379

기본 포트를 피해 매핑해 두었으므로, 로컬에 다른 PostgreSQL·Redis가 떠 있어도 충돌하지 않습니다.

되돌릴 수 없음

완전 초기화는 이 한 줄입니다. 실행하면 계좌·주문·체결·원장·캔들이 모두 사라지고, 다음 기동 때 db:migrate와 db:seed를 다시 해야 합니다.

docker compose --project-name mock-kabu2 down -v

기능

거래소 한 벌이 통째로 들어 있습니다.

주문 · 체결 · 정산

지정가·시장가 주문을 접수하면 잔액·보유를 홀드하고, 매칭 엔진이 가격–시간 우선으로 체결한 뒤 정산 워커가 잔고·보유·원장·캔들을 갱신합니다.

실시간 호가창

호가·체결·계정 이벤트가 Redis Pub/Sub → API 게이트웨이 → WebSocket으로 브라우저까지 밀려옵니다.

캔들 차트 6종

1분·5분·15분·1시간·4시간·1일. 저장은 1분 봉만 하고 나머지는 조회 시 집계합니다. KST가 UTC+9라 일봉은 09:00에 열립니다.

시장 참여자 봇 10개

마켓메이커 3 · 소액개미 3 · 고래 1 · 노이즈 2 · 모멘텀 1. 추세·변동성 군집 기준가를 공유하며 호가창을 계속 살아 있게 합니다.

bot1@bots.local ~ bot10@bots.local / botpassword

전용 유동성 공급자

종목별 reserve 계정 5개가 양방향 각각 약 ₩120M의 호가벽을 유지합니다. 기존 호가를 먼저 채운 뒤에만 교체해 호가 공백과 불필요한 슬리피지를 막습니다.

가상 뉴스

템플릿 105종에서 종목 호재·악재와 매크로 뉴스를 2~4분마다 생성합니다. 강도에 비례해 봇의 매수·매도 확률이 기울 뿐, 반드시 오르지는 않습니다. 후속 보도로 결과가 뒤집히기도 합니다.

실전 리플레이

해외 주식 10종 · KOSPI 5종 · Bitcoin의 고정 일봉을 한 봉씩 공개합니다. 먼저 200봉을 보여준 뒤 1개월(30봉)~3년(1,095봉)을 재생하고, x0.25~x2 속도와 한 봉 진행을 지원합니다.

락 전략 3종

LOCK_STRATEGY로 낙관적 / 비관적(기본) / Redis 분산 락을 전환합니다. 분산 락은 fencing token으로 좀비 쓰기를 막습니다.

멱등성과 안전망

모든 이벤트에 event_id가 붙고 processed_events 테이블로 중복 소비를 무시합니다. DB에는 CHECK(balance >= 0) 제약과 append-only 원장이 있습니다.

체결 흐름

주문 한 건이 지나가는 길

각 단계는 별도 프로세스이고 사이는 Redis Streams로 이어집니다. 전달 보장은 at-least-once, 중복은 멱등성으로 흡수합니다.

api잔액·보유 홀드(락) + orders/outbox를 같은 트랜잭션으로 기록
↓ outbox relayer
Redis Streams · orders심볼별로 순서 보존
↓
matching-enginesingle-writer 오더북, 가격–시간 우선 매칭 → trade 이벤트
↓ Redis Streams · trades
settlement잔액·보유 갱신(락) + 홀드 해제 + 원장·캔들 기록
↓ Redis Pub/Sub
webAPI 게이트웨이가 WebSocket으로 호가·체결·계정 변화를 push

운영 · 복구

검증하고, 어긋났으면 되돌리기

일상 검증

pnpm test               # 오더북 매칭 + 락 전략 단위 테스트
pnpm check:consistency  # 원장 합계=잔액, 음수 잔액·보유 0건, 홀드 불변식

정산이 비정상 종료된 뒤

먼저 비파괴 dry-run으로 미정산 체결과 주문·예약 상태를 함께 검증합니다. 모순이 있으면 아무 데이터도 바꾸지 않습니다.

# api / settlement / matching-engine / bots를 먼저 중지
pnpm recover:settlement

# 출력이 SAFE일 때만 적용
pnpm run recover:settlement -- --apply --confirm=RECOVER_UNSETTLED_TRADES
pnpm check:consistency

체결 이력이 주문 수량과 모순되면 자동 복구는 차단됩니다. 그때는 아래 초기화로 깨끗한 시장을 다시 만듭니다.

깨끗한 상태로 다시 시작

docker compose --project-name mock-kabu2 down -v
pnpm infra:up
pnpm db:migrate
pnpm db:seed
pnpm check:consistency

락 전략 바꾸기

.env의 LOCK_STRATEGY를 바꾸고 api를 재기동한 뒤 /admin에서 충돌·재시도 카운터를 관찰합니다.

값구현
optimisticUPDATE ... WHERE version = ? + 지수 백오프 재시도, 충돌 시 409
pessimistic기본값. SELECT ... FOR UPDATE 원시 SQL, 계좌 ID 오름차순 잠금, lock_timeout
distributedRedis SET NX PX + Lua 해제 + fencing token
